Фаза 0: входной правовой скрининг (GDPR L + AI Act M)

Этот файл описывает актуальную входную бизнес-логику бота. Каноническая подробная версия лежит в docs/system-business-logic.md.

1. Цель фазы

Фаза 0 определяет обязательность GDPR и применимость AI Act до того, как бот начнет профильные вопросы и чек-лист мер.

На выходе фаза должна заполнить внутренние поля сессии:
    • gdpr_status: "anonymous" | "mandatory"
    • gdpr_mandatory: bool
    • attack_risk: bool
    • target: "system" | "model"
    • ai_act_status: "in_scope" | "AIA_OUT_OF_SCOPE"

2. Блок L: квалификация GDPR

L1. Содержит ли датасет персональные данные (ПД)?
    • Yes -> L2
    • No -> M1; gdpr_status = "anonymous"; gdpr_mandatory = False

L2. Модель создана для поиска/выдачи инфо о лицах?
    • Yes -> M1; gdpr_status = "mandatory"; gdpr_mandatory = True
    • No -> L3

L3. Проводились ли атаки на извлечение ПД из весов?
    • Yes -> L4
    • No -> M1; gdpr_status = "mandatory"; gdpr_mandatory = True; attack_risk = True

L4. Риск ре-идентификации признан ничтожным?
    • Yes -> M1; gdpr_status = "anonymous"; gdpr_mandatory = False
    • No -> M1; gdpr_status = "mandatory"; gdpr_mandatory = True

Важно: старые терминальные значения EXIT_ANON, EXIT_GDPR и WARN_ATTACK больше не участвуют в машинной логике. Если они встречаются в Google Sheet, бот воспринимает их только как человеческую пометку.

Google Sheet также может отдавать составное значение перехода:
    • M1 (Флаг: gdpr=True) EXIT_GDPR -> M1; gdpr_mandatory = True
    • M1 (Флаг: gdpr=False) EXIT_ANON -> M1; gdpr_mandatory = False

Если в переходе явно указан gdpr=True/False, этот флаг считается источником правды для gdpr_mandatory. Текст EXIT_* в той же ячейке игнорируется.

3. Блок M: скрининг AI Act

Тексты вопросов M1 и M2 бот читает из вкладки Logic_GDPR. В таблице они должны идти последними строками после L1-L4.

M1. Что именно мы тестируем: независимую ИИ-модель или готовое приложение/систему, куда этот ИИ встроен?
    • Система / Yes -> M2; target = "system"
    • Модель / No -> M2; target = "model"

M2. Связан ли ваш ИИ-продукт с рынком Европейского союза (ЕС)?
    • Yes -> первый вопрос профиля System_Triggers; ai_act_status = "in_scope"
    • No -> ai_act_status = "AIA_OUT_OF_SCOPE"

Если M2 = No и gdpr_mandatory = True, бот сообщает, что AI Act не применяется, но продолжает GDPR-трек.

Если M2 = No и gdpr_mandatory = False, бот завершает аудит, потому что нет обязательного GDPR-трека и продукт вне AI Act.

В System_Triggers есть терминальная проверка prohibited_type. Если пользователь отвечает Yes, бот не запускает чек-лист и финальный отчет, а отправляет большое предупреждение «КРИТИЧЕСКИЙ СТАТУС: ЗАПРЕЩЕНО В ЕС (PROHIBITED AI)» с причиной блокировки и рекомендацией удалить запрещенный функционал или ввести геоблокировку для ЕС.

4. Дисклеймер для anonymous/GDPR-not-mandatory

Для всех исходов, где gdpr_mandatory = False, в пользовательские подсказки и итоговую документацию должен динамически добавляться текст:

«Документация должна позволять регуляторам и пользователям убедиться, что модель не обрабатывает персональные данные».
